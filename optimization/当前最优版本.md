## 采用的优化

| 部分 | 当前实现 | 主要来源 |
| --- | --- | --- |
| 长注意力 | Q128/K32 packed，P 行 LDS、V 预排布、内部 P/ROR4 精简、stable-max guarded、成对 P 算术 | `dcu-kernel-autotune/candidates/pv-v-lds-layout/` |
| 短注意力与 Python attention bridge | 九齿表达和目标平台编译链，按设备、形状、stride 等条件分派 | `adaln/accurate_attention.py`、`../h3/songshan_h3/` |
| Q/K 归一化与 MRoPE | 九齿融合 | `adaln/` |

| SwiGLU | 九齿按行实现，保留 BF16 舍入边界 | `candidates/swiglu-packed/` |
| 分片求和与门控 | 按实际 communicator 校准逐位置 rank 环，九齿完成原序 BF16 求和、门控与残差 | `candidates/peer-sharded-norm/` |
| 行分片归一化与发布 | 每卡只归一化其拥有的完整行，发布完整归一化输入供原 GEMM 消费，末层物化完整 hidden | `candidates/peer-sharded-norm-model/` |
| VAE 调度与条件编码 | 原 VAE 时间窗两卡分派，batch=1，按原顺序混合；首帧采用确定性 DNN 选项；条件编码器 TP=4 | `video_decode_parallel.py`、`adaln/keyframe_determinism.py` |

表内 `candidates/` 相对 `optimization/dcu-kernel-autotune/`。正式配置没有设置 `H3_BENCH_JIT_CACHE`、`H3_ENCODER_PREFILL`、`H3_VAE_CACHE_REPLICAS` 或更大 VAE batch。

VAE D64、RoPE AOT 和时间窗 Graph 等候选仅有独立实验资格。跨卡分链路发布、直接写归约卡、QK 分数物化拆分及 VMM 供数保留实测取舍。正式组合由稳定发布目录的 `candidate.env` 和冻结设备身份确定。

## 重建并运行这一组合

使用完整历史克隆 `xsh-opt`，在统一离线环境中准备 DTK 26.04、GCC 11.4、CPython 3.11、海光 Torch 2.9、比赛依赖、官方首帧和原权重。完整环境步骤见 [环境准备](README.md#准备运行环境)。`runtime` 及本机的 `selected-best.env` 属于部署环境，Git 提交通过下面的显式配置选择版本。

~~~bash
git clone --branch xsh-opt git@github.com:lmf624953-blip/songshanbei.git
cd songshanbei
repo=$(pwd)
git rev-parse HEAD

# 按环境准备文档建立 repo/runtime 后，设置配套 xmake 二进制绝对路径。
xmake_binary=/absolute/path/to/xmake
work=/absolute/path/to/new-best-build
mkdir -p "$work"

# 三阶段依次产生注意力前序、peer 前序和最新行分片组合。
bash "$repo/optimization/reproduce-public-a.sh" build "$work/attention"
bash "$repo/optimization/dcu-kernel-autotune/candidates/rccl-sequence-parallel/build-peer-release.sh" \
    "$work/attention/release/candidate.env" "$work/peer" "$xmake_binary"
bash "$repo/optimization/reproduce-public-a.sh" build-sharded \
    "$work/peer/candidate.env" "$work/sharded" "$xmake_binary"
release="$work/sharded/release"
~~~

三个阶段的输出目录必须尚不存在。若采用源码版 xmake，先配置其配套的 `XMAKE_PROGRAM_DIR`。新构建初始记录 `qualified=false`，身份核对通过后按普通入口及多用例流程验证新环境。当前账号已有稳定发布目录可直接复用。

~~~bash
repo=/public/home/acvduipmem/xsh/songshanbei/submission-xsh
release=/public/home/acvduipmem/xsh/songshanbei/optimization/dcu-kernel-autotune/validated-build/peer-sharded-norm-f13r1n16
model=/work1/share/sugonhpcapp01/zhanghengyu/songshanbei/models/MiniMax-H3

# 串行运行，两个输出目录均须尚不存在。
bash "$repo/optimization/reproduce-public-a.sh" resident \
    "$release" "$model" /absolute/path/to/new-resident
bash "$repo/optimization/reproduce-public-a.sh" single \
    "$release" "$model" /absolute/path/to/new-single
~~~

稳态读取 `new-resident/benchmark.json` 的 `wall.candidate.mean`，协议为 `minimax-h3-public-a-sharded-norm-paired-v1`。进程墙钟读取 `new-single/process-time.txt`。独立推理通过 `run-optimized.sh --config "$release/candidate.env" fl2va` 转交首帧、文本、模型路径及输出等官方参数。
