# VMM 分片输入供数：生产尺寸实测与取舍

2026-11-28，`f13r1n16` 八卡 BW1000。本轮把现用九齿局部归一化的输出写入八卡分片 VMM，再由原 rocBLAS 按需读取；与现用局部归一化→主动发布→相同 GEMM 比较。**当前方案不采用，保留 116.975680 秒正式默认。** 生产 A 的六项检查均逐位通过后做39组配对，但流水线耗时增加约83%–101%。没有为负收益方案运行完整模型。

## 比较范围与数值闸门

两侧均执行现用 `wide_norm_indexed_kernel` 和原 rocBLAS TN、batch1、alpha1/beta0、BF16输入输出、FP32累加、默认算法。HIP仅实现页映射、位复制与事件依赖。矩阵 `N=27570,K=5376`，QKV的M=2688，GateUp的M=3584；没有改变leading dimension、累加顺序或有效token数。

参考按原 `floor(N*rank/8)` 处理完整行，再以5120 blocks发布到各rank本地完整输入。候选的逻辑行划分相同，物理页单独等长对齐；页边界附近允许生产者写入邻卡页，但一个完整行的数学仍由一个rank执行。各rank就绪事件全部完成后才进入GEMM。

计时包含局部归一化、发布或就绪依赖、八卡GEMM与同步，不含共同前驱gate；以八个持久主机worker发射GEMM，记录CPU墙钟及各卡GPU event。数据为合成有限BF16，生产尺寸；每个A变体预热后39组交替顺序配对，不使用profiler。计时前在八卡比较完整归一化输入、完整GEMM输出及norm/输出尾部哨兵，全部逐位通过。

## 独立时间线与 PMC

另开进程，对2MiB、M=2688各采集一次预热后流水线。profiler停止前两秒排空不计入ROI。每卡参考有1个norm、1个publish、1个GEMM；VMM有1个norm、1个GEMM。代表GEMM设备耗时如下，仅用于定位：

| 卡 | 本地输入 GEMM | VMM输入 GEMM |
| --- | ---: | ---: |

| 0 | 2.552639 ms | 4.108318 ms |

| 1 | 2.496638 ms | 5.066076 ms |

| 2 | 2.549919 ms | 7.063356 ms |

| 3 | 2.534399 ms | 7.633437 ms |

| 4 | 2.591839 ms | 9.421116 ms |

| 5 | 2.602078 ms | 9.204792 ms |

| 6 | 2.579519 ms | 9.267834 ms |

| 7 | 2.749919 ms | 9.312634 ms |


参考发布kernel每卡约2.164–2.179ms，候选已取消它，但最慢卡GEMM额外延长更多。参考ROI 5.598237ms，VMM ROI 10.233906ms，八卡全空闲仅0.355502/0.504332ms；主要退化落在设备GEMM执行。GPU0的VMM GEMM只有4.108318ms，无法代表约9.42ms的最慢卡。

两项独立`hipprof --pmc`仅在一个预热后流水线内采集。参考24条记录：8norm/8publish/8GEMM；VMM16条：8norm/8GEMM。八卡GEMM名称完全相同，均为256 VGPR、65536B LDS、0 scratch。原始字段：参考`L2 cache hit rate`77.280%–81.137%，VMM78.201%–85.298%；`L1 cache unit is stalled`分别1.454%–1.777%、0.868%–2.279%。总体缓存指标没有直接说明每个操作数或链路代价，不能将退化简单归因为L2命中率降低，亦不把这些百分比当峰值利用率。

时间线支持本实现的远程供数使GEMM设备执行变慢；细粒度远程读、卡间并发与库内数据复用的各自贡献未分离。未据此宣称所有VMM/其他库调度都不可优化。原始[本地PMC](peer-virtual-input-f13r1n16-local-pmc.txt)与[VMM PMC](peer-virtual-input-f13r1n16-vmm-pmc.txt)完整保留。

## 映射与剩余限制

初版生产初始化在`hipMemSetAccess`失败，尚未计时。改为等长物理区间全部映射后统一设置权限，4KiB/64KiB/2MiB的生产初始化均通过。这两个初始化变化没有单独做因果分离，不把失败简单定性为某页粒度不可用。

另开进程以`hipMemRetainAllocationHandle`和`hipMemGetAllocationPropertiesFromHandle`核对8个区间，返回的device id均与请求的0–7一致，各卡显存增量也一致。显存记账包含rocBLAS上下文和工作区，不能把全部增量当作VMM本体占用。

最初A两种投影后切换B，N=22899/M=2688/rank6观察到完整输入相同而GEMM输出位模式不同，程序按闸门停止；没有接收该B的计时。新进程仅运行B的一次独立检查逐位通过，原因尚未定位，不能宣称跨形状稳定通过。C未执行，计划中的18项生产检查实际完成六项A；鉴于A明显退化，不继续此实现的模型资格。

首个trace封装脚本曾因输出文件名变量拼接导致检查退出1；local采样已完整结束并保留，后续仅补vmm采样，两侧现有ROI均通过CPU汇总。该错误不改动或重跑配对计时。

完整样本、CV、GPU event、数值结果、映射错误、物理归属和独立profiler摘要见[JSON](peer-virtual-input-f13r1n16.json)。大型数据与完整源码快照保留在JSON的experiment路径。正式默认未改动；后续继续审查长注意力的寄存器生存期与跨KV块QK/softmax/PV流水线等尚未验证构造，优先预计超过3%完整请求收益的方向。
