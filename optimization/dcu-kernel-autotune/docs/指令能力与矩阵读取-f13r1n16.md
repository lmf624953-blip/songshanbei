# gfx936 矩阵指令与 LDS 读取验证

在 `f13r1n16` 上使用 DTK 26.04 核对当前 `Q128/K32 packed` 注意力的指令选择。现用 `v_mmac_f32_16x16x16_bf16` 通过编码。此前 `round_029` 强制 `matrix_instr_nonkdim=32` 后没有生成对应矩阵布局，构建未进入计时。本轮直接检查了目标汇编器。

| 检查对象 | 本机结果 |
| --- | --- |
| 已测 BF16 大形状 MMAC、MFMA32、WMMA | 编码失败，原始记录区分无效指令和目标不支持 |
| BF16 单值转换与反向转换 | gfx936 汇编器拒绝，原生打包转换沿用此前拒绝记录 |
| MMAC `cbsz`、`abid`、`blgp` | 已测修饰形式被拒绝 |
| MMAC `lit`、`lts` | `llc` 可打印，目标汇编器明确拒绝三种组合 |
| HCU MMAC `cz` intrinsic | `llc` 目标选择失败，退出 `−6` |
| `ds_read_m32x16_b16` 和 `_alt` | 编码和真实设备标签测试通过 |

最初的 `lit/lts` GPU 探针在构建期间被汇编器拒绝，随后改用独立 CPU 探针记录目标支持差异。原型从候选目录移入实验记录，相关编码未在设备执行。

两条 LDS 指令各测试五种地址模式，并用 `ds_read_b128` 做三个对照。13 个探针各执行两次，覆盖每块 256 个 lane，每 lane 读取八个 BF16 标签。普通读取符合预期，所有探针均通过重复一致性、地址标签、输出边界和输入检查，四个 wave 的结果也一致。

在捕获的模式内，每个输出标签由同一 wave 内指定 source lane 提供的地址和元素偏移决定。对目的 lane 0 和 1，两条指令分别只相差 1 和 2 个 BF16 元素。现用固定布局中，K 对应地址相差 136 个元素，V 与 P 相差 32 个。统一调整各 lane 的输出槽顺序无法消除这一差异。采用矩阵读取需要重新安排生产者布局或增加 lane 交换，现有抓取只支持上述映射和固定布局的判断。

本轮属于编码能力与数据布局诊断，没有形成进入正式配对计时的新注意力实现。官方 A 的已验收结果来自 `peer-sharded-norm-f13r1n16` 的常驻稳态测试，三次均值 116.975680189 秒。

重建命令、诊断脚本与原始记录见 [候选说明](../candidates/instruction-capability/README.md) 和 [JSON 结果](instruction-capability-f13r1n16.json)。完整四 wave 捕获保存在 JSON 指向的实验目录中。
