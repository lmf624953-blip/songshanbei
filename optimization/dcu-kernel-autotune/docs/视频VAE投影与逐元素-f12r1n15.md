# 视频 VAE 投影和逐元素算子的独立对照

当前完整公开 A 的常驻稳态均值为 **116.976 秒**，视频 VAE 解码为 **13.504 秒**，占 **11.54%**。仅靠该阶段缩短完整请求 3%，需要节省约 **3.51 秒**，相当于 VAE 解码缩短 **26.0%**。本轮在 `f12r1n15` 继续核对 VAE 的投影、逐元素发射及时间窗调度。[已验收完整请求分段](行分片归一化模型-f13r1n16.md)

## QKV 权重合并

使用真实 VAE 第 0、17、35 层的 QKV 权重和偏置，配合四种长度、两档幅度的固定种子 BF16 激活。1797-token 下，合并 GEMM 输出保持逐位一致，保留带 stride 的分片视图可节省约 0.016–0.018 ms。恢复连续输出需要额外复制。

| 层 | 1797-token 分片视图降幅 | 1797-token 连续输出降幅 |
| --- | ---: | ---: |
| 0 | +4.65% | −13.19% |
| 17 | +4.74% | −14.33% |
| 35 | +5.24% | −13.77% |

每项 31 组无 profiler 配对。1029-token 的 Q、K、V 每个张量各出现 446–523 个 BF16 位模式差异，两种输出布局均复现。1796、1798-token 输入逐位一致。以较忙卡的 2880 次注意力调用作为投影出现次数的宽松上界，正收益预算约为 0.05 秒，未纳入完整解码候选。三次 GEMM 的累计占时仍有分析价值，后续调优需在保留各形状位模式的前提下比较底层实现。

## 九齿 RoPE 与 SwiGLU

RoPE 首版三维 tile 的 lowering 在计算 head 坐标时直接加了 tile 内元素偏移，少除了 64。1797-token 下，每个 Q 或 K 约有 272 万处位模式差异。改为由一维元素偏移推导 token、通道及旋转配对，保留原两个 BF16 乘积的独立舍入。四个 tile × 七组输入全部逐位通过，覆盖 1029、1796、1797、1798-token 及恒等旋转和四分之一转。通用 JIT 调用链的 31 组交替计时如下。

| tile | 参考中位数 | 候选中位数 | 逐对降幅中位数 |
| --- | ---: | ---: | ---: |
| 256 | 0.504480 ms | 0.769120 ms | −52.11% |
| 512 | 0.502880 ms | 0.763679 ms | −52.59% |
| 1024 | 0.497280 ms | 0.761760 ms | −54.77% |
| 2048 | 0.499680 ms | 0.759360 ms | −52.03% |

独立 hipprof 默认 PMC 的 2048 tile 为 16 VGPR、48 SGPR、0 LDS、0 scratch，kernel time 0.075 ms。生成代码使用标量 BF16 读写。PMC 仅计采样 kernel，配对事件还包含发射路径及同一 stream 的间隙。[默认 PMC 原文](vae-rope-flat-f12r1n15-pmc.txt)

同一一维表达式固定连续布局的 stride 并编为 HSACO，再通过 HIP 模块直接发射。两个 tile 的 14 组检查逐位通过，两侧都在计时内分配输出。

| AOT tile | 参考中位数 | 候选中位数 | 逐对降幅中位数 |
| --- | ---: | ---: | ---: |
| 512 | 0.499680 ms | 0.136000 ms | +72.28% |
| 2048 | 0.494240 ms | 0.222560 ms | +54.87% |

这组实验同时变更布局特化和发射方式，未单独分解两者贡献。AOT 512 tile 的独立 PMC 为 24 VGPR、48 SGPR、0 LDS、0 scratch，kernel time 0.115 ms。按较忙 GPU 的 2880 次 QK RoPE 调用统一取 1797-token 中位数差额，约为 **1.05 秒 / 0.90%** 的完整请求预算。实际长度混合、相邻算子及两卡负载尚未接入测量，单项先归档。[AOT 默认 PMC 原文](vae-rope-aot-f12r1n15-pmc.txt)

SwiGLU 保留 ATen 的 `SiLU(gate) → BF16 → 乘 up → BF16` 边界。两种精确候选覆盖 65,280 种有限 BF16 gate 位模式和普通、放大输入，全部逐位相等。1797-token 的逐对降幅为 **−13.61%** 和 **−13.26%**。快速近似在穷举 gate 与 8 倍输入分别出现 4 处及 15,857 处差异，普通输入的孤立计时仅保留作诊断。

## 原时间窗 HIP Graph

在单卡捕获实际 VAE 的完整时间窗，输入为 `[1, 24, 7, 58, 48]`，保留原输入 stride、空间 tile 和拼接。两份不同 latent 的解码均与即时发射逐位相同，两份参考输出也彼此不同。回放计时包含复制新 latent 和同步，采集成本单列。

七组交替配对的中位数为 **3.194496 → 3.110485 秒**，逐对降幅中位数 **2.61%**。一次捕获约 **1.544 秒**，本诊断进程记录的 PyTorch 峰值约 **7.48 GiB**，其中包含对照输出。单卡每窗的差额约 0.084 秒，按当前较忙卡四窗粗估约 0.34 秒。未验证多卡 Graph 组合和常驻模型显存，现有结果只支持归档单项。

## 后续优先级

第 25 次真实八卡去噪的 GPU0 事件中，GEMM 累计 **445 ms**，分片求和/门控与发布合计 **470 ms**。按完整请求的 49 次调用估算，分别对应约 21.8 秒与 23.0 秒的设备事件预算。优先在这两处找能够减少重复数据搬运或投影临时写回的方案，已有小收益和负结果可用于缩小搜索范围。将 VAE 的 D64 和 AOT RoPE 保留给组合复核。完整请求继续使用已验收的行分片归一化版本。[真实去噪时间线](行分片归一化模型-f13r1n16.md)
