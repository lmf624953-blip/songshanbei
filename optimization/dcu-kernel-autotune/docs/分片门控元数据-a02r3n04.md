# 分片求和与门控的 owner 元数据

在 `a02r3n04`，对现用九齿分片求和/门控比较三个表达。预旋转把八次动态 rank 提取改为一次循环旋转后按固定位置取值。共享 owner 用整个块的整数 min/max 检查一致性，一致时共享标量元数据，混合块保留逐元素选择。两者组合另行测量。

## 数值与配对

九组输入覆盖 27570、22899、24062、24577、4097、17、9 行。包含生产尺寸的 owner 表、逐位置混合 owner、块首尾相同而内部不同的反例、极小值、大幅值及 NaN/Inf。运行时 rank 排列由不同固定种子生成。三个候选共 **216 项八卡全数组位模式和末端哨兵检查全部通过**，随后完成九组 × 39 对、共 **351 组无 profiler 配对**。

| 变体 | 27570 行 | 22899 行 | 24062 行 |
| --- | ---: | ---: | ---: |
| 预旋转 rank 顺序 | −2.17% | +1.87% | +0.81% |
| 块内共享 owner | +1.38% | +1.90% | +0.01% |
| 共享与预旋转组合 | −1.90% | +0.15% | +0.08% |

百分比为各组逐对 GPU event 最大卡耗时下降的中位数。参考和候选使用相同输入、线程池、八个 stream 及同步方式。event 区间还包含 Python/ctypes 发射间隙，结果用于初筛。共享版公开 A 形状的中位数为 3.042077→3.023360 ms。

现用真实模型时间线中，GPU0 的求和/门控累计约 252.46 ms/次 Transformer，49 次约 12.37 秒。按本轮 1.38% 的算子降幅作筛选估算，只约 **0.17 秒 / 完整请求的 0.15%**。该估算没有计入真实模型中的依赖变化，本轮未进入正式模型候选。

## 编译与重建

初版共享表达只比较块端点，且当前前端未保留所需标量归约类型，构建被拒绝。端点检查也不足以证明任意 owner 表的块内一致性，因此改为整个块的 min/max，并加入端点相同、内部不同的数值反例。

当前编译扩展识别九齿生成代码中的两个 owner 归约和相应 rank 循环状态，补充隐式块轴的整数 min/max，并消除 rank 状态的初始向量广播。其他分支和 BF16 运算保持原表达。映射结构不符时构建拒绝。构建期间还修复了辅助模块搜索路径以及循环状态的标量/向量类型不一致，失败日志保留在实验目录。全部 GPU 对照使用最终成功构建。

共享版重新构建后，全部可加载区段、映射及目标信息一致。非加载调试路径导致整文件 SHA 不同，重建证据按加载内容比较。

## 适用范围与取舍

本轮为八卡独立 gate，使用合成 BF16 输入和运行时 rank 排列，未校准当前 InfiniCCL communicator，未接入 norm/publish 或完整模型。原型按镜像元数据传递 16 字节 LDS，后续其他主机桥如需接入，也需审查相应发射参数。

当前三个候选均先归档，完整公开 A 仍沿用已验收 `peer-sharded-norm-f13r1n16` 的 116.975680 秒记录。下一项值得验证的假设是成对 BF16 数据的 rank 选择与打包读写，在保留每个元素原 RNE 的前提下减少重复选择指令。该假设尚未实测。
