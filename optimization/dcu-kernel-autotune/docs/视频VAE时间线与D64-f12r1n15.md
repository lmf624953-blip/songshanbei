# 视频 VAE 时间线与 D64 短序列注意力

在 `f12r1n15` 用 768×928、124 帧对应的固定种子 latent，独立运行现用两卡 VAE 解码。预热和采样结果的完整像素位模式一致。VAE 解码主体是 36 层 ViT。官方形状产生 7 个时间窗、每窗 20 个空间 tile，共采到 5040 次原九齿注意力发射。

| 设备累计事件 | GPU 0 | GPU 1 |
| --- | ---: | ---: |
| 九齿注意力 | 3.796 s | 2.847 s |
| GEMM | 3.496 s | 2.621 s |
| 归一化与归约 | 1.450 s | 1.083 s |
| 其他内核 | 3.949 s | 2.967 s |
| 标注为复制或集合通信 | 0.001 s | 0.002 s |

诊断窗口为 14.303 秒，两卡同时空闲约 0.201 秒。设备累计时间按内核符号分类，各卡之间可重叠。权重副本准备含同步约 76 ms，时间窗调度返回后的拼接含同步约 5 ms。复制工作也可能出现在其他内核，因此以分段测量和设备分类分别保留。原封装只检查无编号的 trace 文件，实际 hipprof 自动导出了六个编号分片，造成封装退出 1。复用全部六份完整分片后通过了 ROI、两卡事件和注意力调用数检查，重建入口已接受分片输出。

## 时间窗 batch

batch=2、3、4 的输出均有限，形状均为 `[1, 3, 124, 928, 768]`，分别出现 **9,953,169、9,578,817、11,805,433** 个 BF16 位模式差异。三者在完整解码数值筛选阶段淘汰。原始预热耗时保留用于复核。

## VAE 注意力 tile

VAE 实际使用 D64，原通用九齿入口用 128 宽 tile。候选针对 D64 编译，保留 K64 在线归约及原 BF16 工作。1797、1029、1796、1798 四种长度、每个变体的普通和 3 倍 Q/K 输入，共 32 组逐位及有限值校验全部通过。以下为 1797-token、32 heads 的 31 组无 profiler 交替配对。

| 变体 | 参考中位数 | 候选中位数 | 逐对降幅中位数 |
| --- | ---: | ---: | ---: |
| Q32 / 4 warps | 1.445440 ms | 1.509760 ms | −4.41% |
| Q64 / 4 warps | 1.449119 ms | 1.247359 ms | +13.81% |
| Q64 / 2 warps | 1.449439 ms | 1.185599 ms | +18.19% |
| Q128 / 4 warps | 1.446719 ms | 1.173120 ms | +18.93% |

独立 PMC 对照与 Q128 候选均为 16 KiB LDS、0 scratch。VGPR 184→248，bank conflict 47.673%→50.303%，L2 命中率 94.472%→91.784%。因此这次提速不适合归因于降低 bank conflict。计时以独立的无 profiler 配对为准。[默认 PMC 原文](vae-decoder-d64-f12r1n15-pmc.txt)

将 18.93% 乘以较忙卡实测的 3.796 秒注意力累计耗时，得到约 **0.72 秒**的单项收益预算，约为已验收完整请求的 **0.61%**。这项微测正收益先归档，保留给后续组合筛选。后续优先核对 VAE 投影 GEMM、FP32 归约与 BF16 转换的成组开销，完整请求采用版本由八卡与成片验证确定。
