# 融合流水线、双 Q 复用与当前热点实测

2026-11-27，在 `f13r1n16` 上复用已验收的 `attention-stable-paired-f12r2n09`，继续验证用户提出的拆分思路及融合内供数优化。本轮没有胜出候选，正式配置及历史完整 A 均值 **127.831000722 秒**不变；这个完整请求成绩来自已有验收，本轮没有重新生成完整视频。

## 拆分与复用的结论

此前已实际实现 QK producer → 全局 FP32 分数 → 在线 softmax/PV consumer，保留原 MMAC、归约和 KV 顺序。27570 / 22016 token 从约 19.20 / 13.06 ms 变成 44.30 / 29.10 ms。即使 producer 降至 120 VGPR，增加的中间分数写回和读回仍抵消收益。27570 token 每次调用增加约 42.66 GB 往返流量。这个拆分形式不采用；结论没有覆盖所有可能拆分方法。[拆分完整记录](qk-split-f13r1n16.json)

本轮进一步避开此前编译器双 Q 版本的 spills，直接从同一九齿生成汇编构造两个 4-wave Q128 组：独立 K/V 与共享 K/V 均为 8-wave CTA、220 VGPR、32 KiB LDS、零 scratch；共享版只让一个组发布完整块 K/V，每个组保持原始计算顺序与私有 P。尾块使用各自 LDS；末尾单 Q tile 的另一个组计算合法 tile 并屏蔽最终写回，所有线程仍经过 barrier。

以下是 39 组无 profiler 交替配对的同轮中位数。正收益百分比见 JSON 中逐对比值，不能由不同实验行直接相减替代配对。

| 候选 | 27570 token，参考 → 候选 | 22016 token，参考 → 候选 | 决定 |
| --- | ---: | ---: | --- |
| 单 Q，仅 SGPR 分配升至 80 | 19.188 → 19.190 ms | 13.063 → 13.069 ms | 接近零变化 |
| 单 Q，SGPR 80、LDS 32 KiB | 19.189 → 21.719 ms | 13.066 → 14.727 ms | 退化约 12.7%–13.2% |
| 双 Q，独立 K/V | 19.188 → 26.954 ms | 13.063 → 17.338 ms | 退化约 32.7%–40.5% |
| 双 Q，共享 K/V | 19.186 → 26.797 ms | 13.062 → 17.232 ms | 退化约 31.9%–39.7% |

共享与独立版另做直接配对，仅追回 **0.574% / 0.636%**。LDS 对照说明增大 LDS 本身有明显代价；剩余退化涉及线程块组织、同步等耦合，不能把全部退化直接归因于线程数，也不能把各项百分比简单相加。独立 PMC 确认上述候选均没有 spills。[原始 PMC](fused-pipeline-f13r1n16-dualq-pmc.txt)

## 融合内专项优化

| 方向 | 27570 / 22016 token 配对收益 | 结论 |
| --- | ---: | --- |
| stable-max guard：OR 树、uniform ones、去冗余 exec mask、FPCLASS | +0.789% / +0.898% | 不足 3% 完整请求门槛，归档 |
| V 简单 zip 布局，PV read2st64 → read_b128 | −5.231% / −5.068% | bank 冲突变大，淘汰 |
| V bankzip 布局，同样使用 read_b128 | −0.113% / −0.444% | 冲突恢复但没有提速，淘汰 |
| P wave 内发布，保留等待、移除对应 workgroup barrier | +0.356% / +0.380% | 小收益归档 |
| P wave 内发布，同时精简等待 | +0.203% / +0.138% | 小收益归档 |

FPCLASS 独立原始 `int32` 位模式探针覆盖 **589836** 个模式，包含 ±0、subnormal、±Inf、SNaN/QNaN，零差异。不能仅根据最终模型输出判断分类指令等价。

V zip 把旧版相距 1024 B 的两个 64-bit 分量置换到相邻 16 B；bankzip 再交换地址位保持 bank 分布。对全部 8192 B 证明双射及自逆，并逐线程核对 32768 B 的目标读取。bankzip 的九齿预排布由编译器插入了不必要的 LDS layout 转换，实验构建器统一生成 TTGIR 的一维输出 layout 后重编译，最终零 shared、零 scratch。所有成本仍包含在算子计时中。

独立 `hipprof --pmc` 原始字段中，参考 `shared memory bank conflict` 约 **0.0213%**，简单 zip 升至 **13.9689%**，bankzip 降回约 **0.0213%**。修复冲突没有让更宽读取胜过现用方案；因此应同时考虑地址映射、供数依赖及指令开销，不能仅按读取宽度或单个 PMC 指标选择版本。[原始 PMC](fused-pipeline-f13r1n16-local-pmc.txt)

12 个候选各通过 95 条通用位模式检查及两个生产长度的普通/放大 QK 配对检查；小于 4096 的检查属于原回退路径。双 Q 另覆盖 4097、8193 的 odd Q tile 和 K 尾块。guard 的 6 个变体另通过共 252 条 V 值边界记录。独立重建核对 11 个设备镜像/主机库，全部加载区段与 ELF 映射一致，其中 10 个逐字节一致，另一个 V 预排布镜像只有非加载内容差异。没有为负收益或低于门槛的单项启动八卡候选回放和完整生成。

## 重建与复用

先按运行 skill 激活环境，`H3_AUTOTUNE_CODE_ROOT` 指向仓库；`selected_attention` 为带原始生成汇编和元数据的正式 attention 目录。每个输出目录必须不存在。以下仅构建实验，均不修改正式默认。

```bash
cd "$H3_AUTOTUNE_CODE_ROOT/optimization/dcu-kernel-autotune/candidates/pv-v-lds-layout"
python build-dualq-no-spill.py "$selected_attention" "$new_independent" --mode independent
python build-dualq-no-spill.py "$selected_attention" "$new_shared" --mode shared
python verify-p-nan-payload.py "$selected_attention" "$new_shared" "$new_edges" --dualq-no-spill
python build-stable-guard-compact.py "$selected_attention" "$new_guard" \
  --reduce-or tree --uniform-ones --drop-exec-mask --fpclass
python build-v-zip-prepack.py "$new_prepack" --layout bankzip
python build-pv-b128.py "$selected_attention" "$new_prepack" "$new_pv" --layout bankzip
python build-p-wave-publication.py "$selected_attention" "$new_wave"
```

`screen-dualq-no-spill.py --help`、`screen-p-paired-sub.py --help` 提供独立或同进程配对入口；`profile-dualq-no-spill.py` 与 `profile-attention-builds.py` 用于另开进程采集 PMC。不得与正式计时并行。完整原始样本、来源 SHA、位模式结果摘要及重建记录保存在 [本轮 JSON](fused-pipeline-f13r1n16.json)，大型 trace 与生成镜像留在 JSON 标明的本机 validation 路径。
