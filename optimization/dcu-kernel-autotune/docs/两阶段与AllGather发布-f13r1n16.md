# 两阶段计算、独立发布与二维网格实验

2026-11-28，`f13r1n16`，八张 BW1000。此次没有选入新候选，正式默认仍为 `validated-build/peer-gate-nt-f13r1n16`。该版本已有官方 A 稳态完整请求 **120.698043 秒**的资格证据，本轮没有重新测出新的完整请求成绩。

## 拆分边界的选择

完整 Transformer 本身由多个 kernel 组成，长注意力融合 kernel 内才同时包含 QK、在线 softmax 与 PV。此前已实现 QK→FP32 分数缓冲→softmax/PV 的严格原序拆分：27570 / 22016 tokens 从约 19.20 / 13.06 ms 退化到 44.30 / 29.10 ms。27570 tokens 单次额外产生约 42.66 GB 分数往返流量，抵消了 producer 寄存器减少的收益。因此不采用这种物化分数的拆分。[此前完整证据](qk-split-f13r1n16.json)

现用分片门控已经把九齿的求和/门控计算与 HIP 发布分开。本轮沿这个较小的边界继续试验：让每张卡只计算固定 RCCL owner，输出紧凑 partial；再单独发布到八卡。它保留各元素原来的 BF16 加法舍入、门控舍入及残差加法顺序。另一个对照完全保留现用九齿连续分片镜像，仅把 HIP 发布换成 InfiniCCL AllGather，纯复制分片，不增加新的求和。

## 无 profiler 配对结果

每行是独立进程内与现用最佳实现的 39 组交替配对，使用同一 InfiniCCL communicator、八个持久工作线程和独立输出。百分比为逐对 GPU 时间比值的中位数，正数表示缩短；不同实验行的参考中位数存在波动，不能直接相减作因果分解。A/B/C 对应元素数分别为 148216320 / 123105024 / 129357312，均来自真实模型，但这里是独立算子流水线，不是完整模型测速。

| 实验 | A 长度收益 | B 长度收益 | C 长度收益 |
| --- | ---: | ---: | ---: |
| 固定 owner，紧凑 partial，保留全卡 reduced 等待 | +0.777% | −3.732% | +1.710% |
| 同上，只移除全卡 reduced 等待 | +1.658% | −4.020% | +0.819% |
| 从输入导出迭代域，保留等待 | +0.164% | −5.482% | −0.099% |
| 从输入导出迭代域，移除等待 | −0.645% | −5.872% | −0.331% |
| 同上，channel 轮转 2，保留等待 | −1.869% | −8.629% | −3.485% |
| 同上，channel 轮转 2，移除等待 | +0.417% | −5.051% | −0.393% |
| 恢复二维网格，保留等待 | +0.873% | −3.450% | +1.553% |
| 恢复二维网格，移除等待 | +1.142% | −2.694% | +2.590% |

| 原九齿连续分片，AllGather 发布 | +0.203% | +1.379% | +4.772% |

所有行均通过全八卡输出和尾部哨兵检查。数值与依赖诊断另开进程，并在输出、消费者缓冲区写入哨兵后，让 GPU 同 stream 立即读取结果；这类诊断包含额外拷贝，已与上述干净计时区分。

A 上最大微测差额为每批约 **0.08896 ms**。仅用于筛选、假定该差额能重复应用于 4900 个融合批次，投影为约 **0.43590 秒 / 0.36115%** 的完整请求收益；这不是模型实测，也不是收益上界。要达到当前 A 完整请求 3%，每批平均需约 **0.73897 ms**，此次证据没有支持这样的收益。因此没有为这些候选再跑真实模型和完整生成。

## 网格与依赖的专项检查

紧凑输出 `[16,capacity]` 被九齿通用后端展平后，channel 和局部 tile 索引引入动态除法。单纯从输入推导 capacity 未消除这些成本。本轮保存原 lowered 源码，再把坐标恢复为二维 `program_id`，同步更改主机 grid；名义 VGPR 从 67 降至 59，LDS、scratch 均为零。独立 CPU 从实际原 lowered AST 求值，在 14 个长度上检查 142779 个坐标，对照二维坐标和输出界限，全部通过。三个生产长度的 GPU 完整数组检查也通过。

独立重建的二维镜像全部可加载区段、常量和 ELF 映射一致；整文件 SHA 因非加载内容变化而不同。恢复二维降低了索引资源需求，但没有得到足以采用的性能收益。

另外直接配对二维 wait→async、展平 async→二维 async，各 39 组 A 长度。前者本轮约 **−0.923%**，后者约 **+0.744%**。这两组是对应选项的直接对照；没有证据说明删除 reduced 等待有可靠的大幅收益。

全部实验保留输入 ready 和发布后完整消费依赖。async 版仅删除全部 reduced 事件等待，依赖同 stream 的计算→发布顺序。主机桥对输入、残差与输出做地址区间重叠检查；对二者分别制造 32 B 偏移的部分重叠，八个工作线程均在校准和计算前正确拒绝。H3 的 residual、gate、indices 必须在 TP ranks 间复制；本实验不适用于这些输入按 rank 不同的任意算子。

## PMC、来源和复用

独立 `hipprof --pmc` 分别限定 `h3_peer_gate_kernel`、`publish_owner`，对照使用原 InfiniCCL 求和加已选门控，避免把现用九齿同名 kernel 混入计数。每份原始 TXT 必须实际包含八卡各三次、共 24 条目标记录，不能只按 hipprof 返回 0 判断采集成功。PMC 运行不计入上面的性能配对。

| hipprof 原始字段 | 二维求和/门控，24 次范围 | 固定 owner 发布，24 次范围 |
| --- | ---: | ---: |
| vgpr count | 60 | 28 |
| sgpr count | 64 | 48 |
| shared memory size / scratch size | 0 / 0 | 0 / 0 |
| shared memory bank conflict | 0% | 0% |
| L1 cache unit is stalled | 3.070%–3.914% | 83.242%–86.736% |
| L2 cache write unit is stalled | 0% | 90.413%–93.572% |

编译器名义 59 VGPR 与 hipprof 的 60 是不同报告粒度，不能混为同一字段。两种 kernel 都没有 LDS bank conflict；发布阶段仍有很高的写等待。原现用发布也有高写等待，不能只按该百分比断言本候选更慢，最终采用决定仍以上述无 profiler 配对为准。
