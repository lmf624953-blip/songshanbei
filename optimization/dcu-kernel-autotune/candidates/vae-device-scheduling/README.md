# 原视频 VAE 窗口的设备调度复测

既有方案在两张 DCU 按原 `tokens_chunk_size`、overlap、batch=1 解码各窗口，保持原顺序混合成片。历史四卡方案只领先两卡约一秒，不能据此声称当前节点有收益。此候选复用现有解码实现，按两卡/四卡交替，排除各设备组合的首次预热，分别验证 928×768 和 768×768、124 帧形状。每轮重算全部窗口，不缓存 latent、视频或输出。

`bench.py --model MODEL_ROOT --output NEW_RESULT` 需要四卡可见和 `H3_AUTOTUNE_CODE_ROOT` 指向交付仓库。返回逐位相等、有限值、形状、完整解码耗时和 Torch 分卡显存峰值；这些独立数字不能代替常驻完整模型的性能与显存验收。当前微测完成，全部输出逐位一致；928×768 的两卡/四卡中位数12.8797/13.5018秒，四卡慢4.83%；768×768为10.6607/10.0472秒，但四卡两样本为10.6316/9.4627秒，波动明显。保留两卡配置。首个独立脚本曾误取模型首参数的FP32 dtype，已按原解码入口改用 `post_quant_conv` 的BF16 dtype后重测；该失败记录在本地保留，不是正式推理故障。参见[复测数据](../../docs/vae-device-scheduling-1218234-micro.json)。
