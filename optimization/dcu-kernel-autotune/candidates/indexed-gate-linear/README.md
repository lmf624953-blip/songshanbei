# 线性索引门控候选

现用门控按 5376 列切成三个 2048 元素分块，最后一个分块存在空余 lane。本候选将输出连续展开后分块，再按列宽恢复行、列及调制表索引，研究减少尾部浪费能否覆盖新增整数除余成本。

计算仍为先将 `gate * activation` 舍入到 BF16，再与 BF16 residual 相加；没有改变模型运算、输入、调用次数或按数据返回结果。固定的是当前模型宽度，行数、调制表行数和索引内容均来自实际输入。编译使用九齿表达及现有受 ABI 检查的 AOT 路径。

`build.py` 只进行 CPU 编译，不更改默认配置。`bench.py` 在同一 InfiniCore stream 对照已验收门控，交替计时，覆盖 1、33、1027、22016、27570 行、3/6 行调制表、放大数值及输出尾部哨兵。微测在本轮完整模型生成退出后串行进行；有可靠收益后才考虑原生守卫、真实八卡、普通官方入口和七请求回归。

首次诊断构建误将一维输出步长设为5376，导致首个N=1测试越界写；已定位并改为1。只允许二维residual/activation/gate首维使用模型行步长，一维indices/output步长均为1，构建清单保留全部动态绑定和常量便于核对。原失败镜像及错误记录保留，不用于模型。修正步长后编译器已统一布局，不把旧错误步长导致的额外LDS转换当作有效优化；相同`.text`候选会跳过重复计时。


修正后的V2完成40项检查，全部逐位一致、有限且尾部保护值保持。8个不同机器码在22016/27570行均慢于已验收逐行门控；最快约0.835/1.039ms，对照约0.560/0.698ms。保留数据，未接入模型，也没有为它追加完整视频回归。
