# 分片门控候选的模型接入状态

目前完成的是八卡独立算子验证，正式最佳配置不变。当前native已验收源码包已提取到本轮validation私有目录，来源SHA在报告中固定。`prepare-native-hook.py` 在该副本生成H3回调patch：回调为空时保留原路径；启用时仅在H3 attention输出投影、FFN down投影中保留本地矩阵结果，把原BF16 AllReduce移到后续门控融合回调。矩阵计算和模型层数不变，两个投影均无bias。准备脚本拒绝未知的基准源码SHA。

新回调、局部投影计数器及私有patch已经形成。尚未实现回调主机桥、未链接或装载新的native库，也未进行真实去噪验收。不能仅凭这个patch或独立算子收益切换正式默认。

## 接下来执行的顺序

1. 在主机桥收集八个`RankWorker`回调，记录各rank输入就绪事件。最后到达的worker向各原始stream加入输入依赖，发射分片门控、推送和发布完成依赖，再释放其他worker。已有代码证实每rank有独立worker线程，因此可使用主机条件变量；不得对单线程顺序调度假定这个同步方式成立。每次回调恢复调用线程的原设备。
2. 不把本机rank环硬编码当通用资格。每个新count/communicator需校准或验证实际rank环、活动通道、块与尾部映射；可用合成BF16探针验证所有位置。验证不符时，回调对真实局部矩阵结果执行原RCCL，再执行现用九齿门控。不得回退为已经少算或重复加过bias的输入。
3. 把rank环作为运行时kernel参数，工作区和位置表按count复用。该状态是算子工作区和通信元数据，不启用跨进程编译缓存。其他TP大小、图录制或不满足源布局的路径沿用原实现。
4. 复用已验收源码快照和已有构建工具，生成独立native overlay，保留当前库。先验证关闭回调时的行为及计数，再在同一驻留模型中切换候选，覆盖早、中、晚三组真实八卡去噪输入。对照是当前selected版本的实际输出，不拿历史旧capture的输出字段代替。
5. 只有真实八卡收益及完整输出通过后，才执行官方普通入口、50 steps/124帧/seed42/768×928、49次Transformer及完整计算检查，随后按现有协议完成稳态A配对、B/C/返回A及质量、显存回归。最终收益以完整请求实测为准；同时记录新增校准、工作区和同步开销。

现用源码包位于已验收native构建的`InfiniLM-applied-source.tar.gz`；新的克隆可通过现有正式构建入口生成相同的应用补丁源码，再运行准备脚本。不要覆盖当前`H3_ADALN_BUILD`所指目录。

运行时校准可沿用本轮探针：在原count上对各rank的32个有限BF16模式做一次重复填充AllReduce，从少量位置推断候选rank环，再用GPU按位置验证完整数组的`signature[owner, index % 32]`。必须根据实际结果确认通道与尾块模型；不符时回退。将rank环压成24-bit参数传入kernel，可避免为拓扑重新编译。模型桥需在每rank原stream记录输入ready，再由最后到达的worker向所有stream加入这些依赖，随后调用分片/推送并完成发布依赖；仅有分片完成事件不足以保证输入GEMM已在其他卡完成。
