# 最优版本整合、规则核查与复现说明

## 本次版本选择

本次上传完整源码、构建链、实验取舍和验证材料。默认发布保持 `peer-sharded-norm-f13r1n16`，其历史八卡 BW1000 完整稳态请求均值为 **116.975680 秒**。最新的七进程 VAE 调度是当前最快的实测候选，保留显式开启方式；它已经通过完整模型、普通默认入口、多用例与稳定性检查，但尚未完成有效的独立时间线/PMC及统一发布整合，不能标为已完成全部发布资格。

| 版本 | 节点与比较口径 | 完整请求均值，含MP4 | 状态 |
| --- | --- | ---: | --- |
| `peer-sharded-norm-f13r1n16` | `f13r1n16`，双方预热后的三组配对 | 116.975680 s | 当前默认、完整发布资格已通过 |
| 同一稳定实现的本轮对照 | `a02r3n04`，同一模型实例、只关闭VAE进程调度 | 118.966930 s | 本轮候选的有效对照 |
| 稳定Transformer + 七进程VAE | `a02r3n04`，同一模型实例、只开启VAE进程调度 | **107.276659 s** | 常驻与普通入口通过，发布候选 |

七进程候选相对**本轮同节点对照**减少9.826488%的完整请求耗时。不能直接以116.975680与107.276659计算优化收益：两者来自不同节点与实验。107秒是模型常驻、两侧完整预热后的生成请求；不包含最初模型加载和工作进程创建。

## 整合的实现

当前默认包含Q128/K32 packed长注意力、P行LDS与V预排布、在线softmax和成对P算术、九齿Q/K归一化与MRoPE、原序宽RMSNorm/indexed AdaLN、逐行SwiGLU、原序BF16分片求和与门控、行分片归一化与末层物化。组件、源码位置和从源码重建步骤见[当前最优版本](当前最优版本.md)。

最新候选只把原独立VAE时间窗交给七个子进程与七张设备执行，仍调用原 `_decode_clip`、使用同一权重、batch=1，并保留原padding、重叠混合、窗口顺序及最终裁剪。CPU IPC传递本次请求的latent和窗口输出，搬运、同步、GC与拼接均计入每次请求。没有返回历史成片或保存可复用的历史模型输出。模型实例、分配器容量和编译器自身已有缓存的正常复用如实记录，未启用 `H3_BENCH_JIT_CACHE` 优化。

| 本轮分项 | 两卡线程对照 | 七进程候选 |
| --- | ---: | ---: |
| 完整请求 | 118.966930 s | 107.276659 s |
| 49次Transformer | 97.200629 s | 97.190696 s |
| 视频VAE解码 | 14.708198 s | 3.798224 s |
| 首帧VAE编码 | 0.861905 s | 0.862199 s |
| 条件编码 | 0.307238 s | 0.307573 s |
| 音频VAE解码 | 0.243029 s | 0.242175 s |
| 媒体写出 | 1.563226 s | 1.514305 s |

分项含嵌套且未穷尽所有宿主/管线开销，不能直接相加解释完整请求。该候选的主要收益来自VAE并行调度，Transformer数值实现和约97.2秒耗时保持一致。

- 方形、1/2/8个时间窗、变更latent值和返回A的原始BF16解码逐位一致；连续32次A的七worker在GC后当前分配量保持一致。独立回归共52条记录。
- 同样七张卡的线程/进程对照完整输出逐位一致，中位数13.541446/3.811410秒。此诊断未把进程收益唯一归因于GIL。
- 本次只读审计再次核对稳定native/桥/设备镜像、151项实际运行源码、11次常驻及1次普通入口成片、入口与比较脚本身份。复用有效实验，没有重跑全套基线或重新散列全部模型权重。
- 独立hipprof运行和七worker退出均成功，但原生JSON导出日志出现 `invalid_argument / stoull`。原始数据库和日志保留在本地；没有把退出码0当作完整时间线有效，也没有把profiler计时用于正式收益。有效时间线、独立原生PMC及候选的统一发布入口仍待补齐。

## 时间与显存的实际代价

七进程候选的独立普通入口 `process.wall=1042.59 s`、Python `total.end_to_end=982.118 s`、首次 `generation.pipeline_total=322.821 s`，首次视频VAE阶段172.395秒含工作进程创建与首次运行。不能把这些时间与常驻107.276659秒混写。

普通入口五秒整卡采样最高39,784 MiB。11请求全程采样最高41,684 MiB，还包含B/C和条件编码器容量扩展；五秒采样可能漏掉瞬时峰值。每worker GC后当前分配量5,611,481,088 bytes。该方案提高稳态效率，同时增加显存和进程初始化成本；赛事性能与资源合占30%，现有文件没有足够的细化计分公式据此保证总分最高。

## 复测命令

先按[环境与重建文档](当前最优版本.md#重建并运行这一组合)准备 `runtime` 与已构建的稳定组合。跨账号不能直接使用本机绝对路径中的二进制或历史资格目录；应先重建并产生本地有效的参考与资格材料。已有账号环境可复用下列稳定目录。

~~~bash
repo=/public/home/acvduipmem/xsh/songshanbei/submission-xsh
stable=/public/home/acvduipmem/xsh/songshanbei/optimization/dcu-kernel-autotune/validated-build/peer-sharded-norm-f13r1n16
model=/work1/share/sugonhpcapp01/zhanghengyu/songshanbei/models/MiniMax-H3

# 默认完整发布的稳态测量；输出目录必须尚不存在。
bash "$repo/optimization/reproduce-public-a.sh" resident \
    "$stable" "$model" /absolute/path/to/new-stable-resident
~~~

七进程完整资格复用已验收版输出做回归，同时比较同实例off/on。`accepted` 在其他部署中应替换为当地新产生的有效资格目录；不能凭此示例路径假定已通过验收。为了避免环境残留，使用新Bash和独占八卡，串行执行。下面的 `new-vae-work` 及其所有输出均为新目录。

~~~bash
repo=/public/home/acvduipmem/xsh/songshanbei/submission-xsh
stable=/public/home/acvduipmem/xsh/songshanbei/optimization/dcu-kernel-autotune/validated-build/peer-sharded-norm-f13r1n16

work=/absolute/path/to/new-vae-work
mkdir -- "$work"
python - "$stable/candidate.env" "$work" <<'PY'
from pathlib import Path
import shlex, sys
source, work = Path(sys.argv[1]).resolve(strict=True), Path(sys.argv[2]).resolve(strict=True)
(work / "candidate.env").write_text(
    "source " + shlex.quote(str(source)) + "\n"
    + "export H3_VAE_PROCESS_WORKERS=7\n"
    + "export H3_VAE_PROCESS_LOG_DIR=" + shlex.quote(str(work / "workers")) + "\n")
PY
export H3_AUTOTUNE_MODEL="$model"
bash "$repo/optimization/dcu-kernel-autotune/candidates/vae-process-scheduling/qualify.sh" \
    "$work/candidate.env" "$work/qualification" "$accepted"
~~~

稳态结果读取 `qualification/benchmark.json` 中 `wall.candidate.mean`，协议为 `minimax-h3-public-a-vae-process-paired-v1`。同一JSON保留对照、三个样本与预热记录；`full_release_qualified=false` 是当前候选的预期状态。普通默认入口另测：

~~~bash

    "$work/candidate.env" "$work/official"
~~~
